**A complete, self-contained account of every verification performed in this
repository: what is checked, by which machine, with which method, which
numbers came out, what the verdict is, which caveats apply, and the exact
commands to reproduce it.**

Everything in this document is generated by the machines of
[`einstein_direct/`](../einstein_direct/) and re-checked by its pytest suite
(21 tests). No number below is fitted, tuned or hand-adjusted; where a
comparison to a published constant is made, the comparison anchor is named
explicitly and is never used inside a computation.

# Part I — Foundations

## 1. The discipline

Every machine in this repository implements the same contract:

> **hypothesis → machine confirmation → honest caveats and limitations.**

Concretely, this means four rules that the whole pipeline obeys:

1. **No fitting.** Literature constants — γ_Ch = 0.374, b_Ch = 0.37651,
   Δ_GHS = 3.44 ± 0.02, the spinor ladder built on π/30 — may appear in
   outputs only as labelled comparison anchors. No machine takes them as
   input to a computation whose output is then compared to them.
2. **Negative results are results.** The mass-scaling floor of the
   fixed-grid campaign, the depth wall of the zoom campaigns, the refusal of
   the live tower, the non-selection of the survivor brick by the tick
   obstruction — all of these are documented verdicts, kept with the same
   status as confirmations.
3. **Every number is traceable.** Each campaign writes a UTF-8 JSON into
   `einstein_direct/results/` with its full configuration, verdicts and
   honest notes. The pytest suite re-reads those JSONs and re-asserts the
   major theorems.
4. **Code is not edited to make tests pass.** If a test fails, the machine
   is re-run and both the JSONs and the code are regenerated together.

## 2. Environment and reproducibility

- Python ≥ 3.9 with NumPy, SciPy, SymPy, matplotlib, pytest; mpmath at
  50 working digits for the symbolic layer.
- All numerical machines force single-threaded BLAS/LAPACK
  (`OPENBLAS_NUM_THREADS = OMP_NUM_THREADS = MKL_NUM_THREADS =
  NUMEXPR_NUM_THREADS = 1`). This is deliberate: multithreaded LAPACK
  reshuffles the summation order inside near-critical bisection and horizon
  nucleation and destroys run-to-run reproducibility.
- The same pipeline runs unchanged on Android/Termux (see
  [`termux/`](../termux/)); the `--quick` profile lowers grid sizes only and
  keeps every protocol step.
- Figures are rendered at 300 dpi from the same runs that write the JSONs,
  in parallel RU and EN variants.
