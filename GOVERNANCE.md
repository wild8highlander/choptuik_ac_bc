## Как принимаются изменения

1. **Issue/PR по шаблонам** — все изменения проходят через шаблоны
   [`.github/ISSUE_TEMPLATE/`](.github/ISSUE_TEMPLATE/) и
   [`.github/PULL_REQUEST_TEMPLATE.md`](.github/PULL_REQUEST_TEMPLATE.md)
   (включая блок **Verification Impact** — оценку влияния на верификацию).
2. **Машина важнее мнения** — изменение чисел требует нового машинного вердикта
   (JSON) и обновлённого пина в pytest; «согласовать число» без прогона машины нельзя.
3. **Статусы не повышаются вручную** — exact / measured-law / honest-negative /
   hypothesis меняются только закрытым ядром (Lean), точным символьным выводом
   (SymPy) или детерминированной кампанией с JSON-вердиктом.
4. **CI-ворота** — pytest-сьюты всех пакетов, lint, link-check; релизы подписываются
   sigstore (`release.yml`).
5. **Публичные отзывы** — ошибки исправляются через формальные ERRATUM-записи
   в реестрах честности (см. README → Реестр честности), а не тихими правками.

## Вклад внешних участников

Приветствуются: сообщения о расхождениях воспроизведения (шаблон
*Verification Discrepancy* — самый ценный вклад), исправления документации,
независимые перепроверки (см. [CONTRIBUTING.md](CONTRIBUTING.md) и
[SUPPORT.md](SUPPORT.md)). Внешние PR не изменяют научные статусы и вердикты —
они передаются мейнтейнеру для машинной перепроверки.
